# 柒.1.4 迭代器模式

你做一个网盘，文件夹里面还有文件夹，一层又一层。现在产品要求按顺序列出所有文件，你总不能每增加一层目录，就多补一层循环吧？

迭代器想解决的，就是**外面的人不必知道你里面怎么存，每次要一个元素就行**。JavaScript 里其实天天在用这套思路，只是很多朋友没注意。

## 01. 你每天都在用，只是没注意

先别急着写自己的迭代器。看看平时再熟悉不过的 `for...of`，为什么数组能遍历，Set 也能遍历？背后其实有一套共同约定：

```javascript
const books = ['前端内参', '设计模式', '算法'];
for (const book of books) console.log(book);
```

`for...of` 不需要知道数组底层怎么存储。换成 `Set` 也能遍历：

```javascript
const titles = new Set(['前端内参', '设计模式']);
for (const title of titles) console.log(title);
```

为什么两种容器都能用？因为它们遵守同一种**可迭代协议**：提供 `Symbol.iterator` 方法，返回一个有 `next()` 方法的迭代器。

## 02. 手写一个“从2数到5”的迭代器

![迭代器如何用统一的 next 方法依次提供元素](../.gitbook/assets/teaching-illustration-iterator.jpg)

> **看图提示：** 不同容器都可以通过迭代协议交出一个带 `next()` 的迭代器；`done` 是 `next()` 返回结果中的布尔属性，不是另一个方法。

先不要用生成器，亲手理解协议：

```javascript
function range(from, to) {
  return {
    [Symbol.iterator]() {
      let current = from;
      return {
        next() {
          if (current <= to) {
            return { value: current++, done: false };
          }
          return { value: undefined, done: true };
        }
      };
    }
  };
}
const nums = range(2, 5);
console.log([...nums]); // [2, 3, 4, 5]
console.log([...nums]); // 再次遍历仍是 [2, 3, 4, 5]
```

这里最重要的是 `[Symbol.iterator]()` 每次调用都创建新的 `current`，因此两次循环互不干扰。

`next()` 返回两样东西：`value` 是当前值；`done` 告诉调用方“还有没有下一项”。调用方不需要知道数据来自数组、网络还是某个计算过程。

## 03. 生成器：帮你省掉手写next

```javascript
function* range(from, to) {
  for (let i = from; i <= to; i++) yield i;
}

for (const n of range(2, 5)) console.log(n); // 2 3 4 5
```

`yield` 像是把函数按下暂停键。下一次 `next()` 来了，再从暂停处继续。它很适合数据量大、不能一次性全部计算的场景。

但要注意：调用一次生成器函数得到的**生成器对象通常只能向前消费**。想重新从头遍历，再调用一次生成器函数就行。

## 04. 实际开发：遍历一棵目录树

先构造一棵简单的文件树：

```javascript
const root = {
  name: '根目录',
  children: [
    { name: '说明.txt' },
    { name: '图片', children: [{ name: '封面.png' }] }
  ]
};

function* walk(node) {
  yield node.name;
  for (const child of node.children ?? []) {
    yield* walk(child);
  }
}
console.log([...walk(root)]);
// ['根目录', '说明.txt', '图片', '封面.png']
```

`yield*` 会把子生成器产生的值一个个交给外层。这里是深度优先遍历；如要广度优先，就使用队列。

这段代码也说明了迭代器与“数组循环”的区别：**它不要求你提前把整棵树拍平成一个数组**，使用者边遍历边得到数据。

## 05. 异步迭代器还能遍历网络数据

```javascript
async function* fakePages() {
  yield ['第一页A', '第一页B'];
  await new Promise(resolve => setTimeout(resolve, 50));
  yield ['第二页A'];
}

(async () => {
  for await (const page of fakePages()) {
    console.log(page);
  }
})();
```

分页 API、持续生成的日志、流式响应适合这种思路。真实网络分页还应考虑失败重试、提前停止和取消请求。

## 06. 面试别踩这几个坑

这几个概念特别容易弄混：`for...in` 和 `for...of` 不是一回事，数组展开和对象展开也不是一回事。

面试里别急着报 API 名字，先看看遍历的究竟是**属性名**，还是按迭代协议一个个产出的值。

- `for...in` 遍历的是对象可枚举字符串属性名，不是同一回事；迭代数组常用 `for...of`。
- 普通对象 `{a:1}` 默认不可用 `for...of`，除非自己实现迭代协议。
- `[...obj]` 需要对象可迭代；`{...obj}` 则是复制可枚举自有属性，两者规则不同。
- 如果集合数据可能无限生成，千万别直接 `[...infiniteIterator]`，那会一直消费下去。

**什么时候用？** 对外提供统一遍历接口、惰性生成大量数据、自定义树结构时最有用。如果只是遍历现成数组，直接使用语言自带迭代器即可，不要为了模式额外造一层轮子。

迭代器最有意思的地方，在于让别人不用管你内部的存储方式。结构可以改，只要对外遍历的约定没变，调用方就能少受影响。
