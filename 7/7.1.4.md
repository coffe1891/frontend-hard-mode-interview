# 柒.1.4 迭代器模式

迭代器模式要解决的是：**调用者只想逐个读取元素，不想关心容器内部用数组、链表还是树来存放数据。** JavaScript 已经为它提供了语言级协议。

## 01. 可迭代对象与迭代器

可迭代对象实现 `Symbol.iterator()`，返回一个迭代器；迭代器的 `next()` 返回 `{ value, done }`。`for...of` 和数组展开语法都遵循这套协议。

```javascript
function range(start, end) {
  return {
    [Symbol.iterator]() {
      let current = start;
      return {
        next() {
          return current <= end
            ? { value: current++, done: false }
            : { value: undefined, done: true };
        }
      };
    }
  };
}

console.log([...range(2, 5)]); // [2, 3, 4, 5]
for (const item of range(1, 3)) console.log(item);
```

每次调用 `range[Symbol.iterator]()` 都获得新的迭代器，所以可以独立遍历。同样的逻辑还可以用生成器写：

```javascript
function* rangeGenerator(start, end) {
  for (let i = start; i <= end; i++) yield i;
}
console.log([...rangeGenerator(2, 5)]);
```

## 02. 四个常见误区

1. `for...of` 遍历值，`for...in` 枚举字符串属性名，二者不同。
2. 普通对象默认不可迭代；对象展开 `{ ...obj }` 也不是 `for...of`。
3. 一个生成器**对象**通常消费一次就不能重新从头遍历；要重新调用生成器函数。
4. 异步迭代使用 `Symbol.asyncIterator` 和 `for await...of`，不能与同步迭代器混为一谈。

## 03. 什么时候用？

当你要暴露分页数据、树遍历、惰性序列，又不想让调用者依赖内部结构时，用迭代协议很合适。仅仅遍历数组时直接使用 `for...of` 即可，不用为了模式而额外造轮子。
