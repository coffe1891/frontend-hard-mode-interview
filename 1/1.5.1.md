# 壹.5.1 为什么需要服务器端 JavaScript：Node.js？

JavaScript 最早服务于浏览器。后来，Web 应用越来越复杂：页面需要接口、构建工具需要运行、前后端需要共用某些业务规则。**Node.js 的价值，是让 JavaScript 能运行在浏览器以外的环境，而不是让浏览器代码原样搬到服务器。**

## 01. Node.js 究竟是什么？

Node.js 是 JavaScript 运行时，使用 V8 执行 JavaScript，并提供文件、网络、进程等浏览器里通常没有的 API。它不等于一门新语言，也不等于 Express 这样的 Web 框架。

Node.js 的 JavaScript 代码通常跑在一个主线程上，I/O 可以交给操作系统或运行时的后台机制处理。说它“单线程，所以所有工作只能串行执行”是错误的；说它“异步，所以 CPU 密集型任务不会阻塞”同样错误。

## 02. 一个不依赖框架的 HTTP 服务器

```javascript
// 保存为 server.cjs，执行 node server.cjs
const http = require('node:http');

const server = http.createServer((request, response) => {
  response.writeHead(200, { 'content-type': 'application/json; charset=utf-8' });
  response.end(JSON.stringify({ message: '你好，Node.js', path: request.url }));
});

server.listen(3000, () => console.log('http://localhost:3000'));
```

这里 `createServer` 收到请求后调用回调函数；响应写回客户端。生产服务还需处理超时、错误、输入校验、日志、鉴权与部署。

## 03. Event Loop 与线程池

```javascript
console.log('A');
setTimeout(() => console.log('C'), 0);
Promise.resolve().then(() => console.log('B'));
// A、B、C
```

Promise 的后续处理进入微任务队列；定时器回调由事件循环在合适阶段执行。**不要**据此推断所有 Node 事件循环阶段的完整顺序；那是更复杂的问题。

如果做大规模加密、图片处理、压缩等 CPU 密集型工作，应评估 Worker Threads、独立服务或专用任务队列。仅仅改成 `async function` 并不会自动获得并行计算。

## 04. 什么时候使用？

常见用途包括：Web API、SSR/服务端渲染、BFF（为前端量身定制的后端）、脚手架、构建工具和自动化脚本。

**面试要点：** 分清运行时与框架、异步 I/O 与 CPU 并行、CommonJS 与 ESM、服务端安全边界。共享语言不能替代对后端数据与权限模型的理解。
