# 壹.5.1 为什么需要服务器端JavaScript：Node.js？

你会写浏览器 JavaScript，已经能操作按钮、表单和页面。但产品经理突然说：“用户上传图片后，要压缩、存到服务器，再通知其他用户。” 这时仅凭浏览器代码做不到可信的统一处理。

浏览器和服务器的工作环境完全不同。浏览器有 `document`、`window`；服务器需要文件系统、网络端口、进程管理等能力。

**Node.js就是让JavaScript可以在浏览器之外运行的一套运行环境。** 它不是一个全新的 JavaScript 语言，也不等同于某个 Web 框架。

## 01. Node.js、V8和浏览器是什么关系？

浏览器用 JavaScript 引擎执行代码，也提供 DOM 等 Web API。Node.js 使用 V8 执行 JavaScript，并另外提供文件、网络、进程等 API。

```javascript
// node-demo.js
console.log('Node 版本：', process.version);
console.log('工作目录：', process.cwd());
console.log('是否存在 document：', typeof document); // undefined（通常）
```

运行：

```bash
node node-demo.js
```

注意：现代 Node.js 也实现了一部分 Web 标准 API，如 `fetch`；但它仍不提供浏览器的完整 DOM。不要以为 JS 语法一样，两端的所有 API 就一样。

## 02. 从零写一个HTTP服务器

下面不装 Express，也不装任何第三方依赖：

```javascript
// server.js
const http = require('node:http');

const server = http.createServer((req, res) => {
  if (req.method === 'GET' && req.url === '/hello') {
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify({ message: '你好，Node.js' }));
    return;
  }

  res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('Not Found');
});

server.listen(3000, '127.0.0.1', () => {
  console.log('访问 http://127.0.0.1:3000/hello');
});
```

运行 `node server.js`，打开浏览器访问 `/hello`，就得到 JSON 响应。看清楚两件事：

1. `createServer` 注册的是“每次请求进来时要做什么”。
2. `res.end` 结束响应，不调用它可能导致客户端一直等待。

真实系统还要做参数校验、超时、日志、鉴权、错误处理等，但最底层的请求/响应概念就是这样。

## 03. 为什么Node能同时处理很多连接？

Node 的 JavaScript 通常由事件循环在一个主线程中执行。遇到网络 I/O，运行时可以把等待交给底层设施；等操作有结果，再把对应回调或任务排入事件循环。

这意味着它不需要“每来一个请求就创建一个 JavaScript 线程”。但是千万别从这里推导出“Node 所有工作都在一个线程完成”：底层 I/O、线程池、Worker Threads 等机制都可能参与。

## 04. 一个会卡住服务的反面示例

```javascript
const http = require('node:http');
http.createServer((req, res) => {
  const start = Date.now();
  while (Date.now() - start < 3000) {
    // 仅演示：阻塞主线程3秒
  }
  res.end('完成');
}).listen(3001);
```

此时即使只有两个用户同时访问，第二个请求也可能被前一个请求的同步死循环耽误。

如果换成等待一个异步计时器：

```javascript
const http = require('node:http');
http.createServer(async (req, res) => {
  await new Promise(resolve => setTimeout(resolve, 3000));
  res.end('完成');
}).listen(3002);
```

等待期间主线程可以处理其他回调。区别不在于“代码里有没有 await”，而在于**真正耗时的事情是否仍然占着 JavaScript 主线程**。

计算密集型任务需要考虑 Worker Threads、子进程、队列或其他架构。把计算函数包进一个 `async`，并不能自动把它放到别的线程。

## 05. Node.js适合什么，不适合什么？

常见应用包括 API 服务、SSR、实时通信、前端构建工具、命令行工具和自动化脚本。I/O 密集型任务通常是强项。

如果主要工作是 CPU 高强度视频编码、复杂数值计算，就要评估任务拆分和计算环境，不应该无条件把所有计算塞进同一个事件循环。

## 06. 面试追问：别把事件循环背成顺口溜

**Promise回调和setTimeout哪个先？** 在具体执行环境和时机下要区分微任务、计时器阶段及 I/O；不要只凭一句“Promise永远先于setTimeout”做无条件推论。

**Node是不是单线程？** 说“JavaScript 执行的主线程通常是单个事件循环线程”更准确。底层还有其他线程和进程机制。

**为什么要用服务器做权限校验？** 浏览器端代码可以被用户修改，权限、价格、支付等关键业务必须由可信的服务端验证。
