# 肆.3.1 高效使用 VS Code 的十点建议

编辑器最有价值的地方不是“安装了多少插件”，而是减少找文件、重复修改、查错和沟通的时间。

## 01. 十个值得养成的习惯

1. **先学命令面板**：通过 `Ctrl/Cmd+Shift+P` 搜索功能，不必记住每个菜单位置。
2. **善用快速打开**：`Ctrl/Cmd+P` 通过文件名跳转，通常比一层层展开目录快。
3. **跨文件符号搜索**：知道函数名但不知道文件位置时，使用工作区符号搜索。
4. **重命名用 Rename Symbol**：比全局字符串替换更安全，不过仍须检查语言服务器对动态代码的识别能力。
5. **多光标与批量编辑**：适合规律性重命名，但涉及语义改动时优先用重构操作。
6. **Format on Save**：配合团队统一的 Prettier/ESLint 配置，避免各人格式不同。
7. **Problems 面板**：优先处理编译、类型和静态检查的问题，而不是等到运行时报错。
8. **集成终端与任务**：把测试、构建和格式检查放在项目脚本里，减少“只在我电脑能跑”。
9. **断点调试**：掌握条件断点、调用栈、变量监视，不要只用 `console.log`。
10. **工作区配置与 Settings Sync**：个人偏好可同步；团队共享设置要保持克制，不能把个人路径和密钥提交进仓库。

## 02. 一个务实的团队配置

`.vscode/settings.json` 可以放团队共同认可的设置，例如：

```json
{
  "editor.formatOnSave": true,
  "files.trimTrailingWhitespace": true,
  "editor.tabSize": 2
}
```

如果团队使用多种语言，应按语言分别指定 formatter；不要默认某个扩展在所有成员的机器上都安装。

## 03. 面试加分项

面对陌生项目，能快速找到入口文件、定位组件引用、启动单元测试并用断点解释 Bug，通常比展示一串插件清单有说服力。
