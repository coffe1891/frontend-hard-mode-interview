# 肆.3.1 高效使用VS Code的十点建议

你每天在编辑器里待六七个小时。如果每次找文件都要点开七层目录，每次重命名变量都靠全局替换，每次调试都靠 `console.log`，时间会像漏水一样慢慢流光。

提高编辑器效率，不是安装五十个插件，而是养成几套稳定的操作习惯。

## 01. 第一个习惯：用命令面板找功能

按 `Ctrl+Shift+P`（macOS 通常是 `Cmd+Shift+P`），输入你想做的事，比如“Format Document”。不用记住每个功能藏在哪层菜单。

**实战练习：** 打开一个 JSON 文件，执行格式化命令，观察缩进是否变化。找不到命令时，先检查相关语言支持和扩展是否安装。

## 02. 第二个习惯：按文件名跳转

按 `Ctrl+P`（macOS 为 `Cmd+P`），输入文件名，直接切过去。

**实战练习：** 打开一个包含几十个组件的项目，随机找三个文件，看自己是否能不碰鼠标完成导航。

## 03. 第三个习惯：重命名符号，不要乱替换字符串

如果一个函数叫 `getUser`，项目里很多文件都引用它。使用 **Rename Symbol** 可以让语言服务按语义尝试修改引用，而不是把注释、普通文本里碰巧相同的单词全改掉。

但这个操作也不是万能的，动态属性访问和跨语言引用可能识别不全。完成后仍要查看 Git diff。

## 04. 第四个习惯：真正学会多光标

`Alt+Click`（不同系统与设置可能有区别）可以在多个位置放光标；还可以通过命令面板搜索“Add Selection To Next Find Match”等操作。

假设 CSV 中有十行重复结构，批量修改同一列内容，多光标比逐行修改快得多。

## 05. 第五个习惯：查引用比查字符串靠谱

你想知道 `calculateTotal` 在哪些地方被调用，可以优先使用 **Find All References**，而不是全仓库搜同名字符串。前者借助语言分析，通常能更准确识别真正引用。

## 06. 第六个习惯：断点调试

调试一个计价函数时，别只看最终结果：

```javascript
function total(price, count, discount) {
  const subtotal = price * count;
  const result = subtotal * discount;
  return result;
}
console.log(total(20, 3, 0.9)); // 54
```

在 `const result` 那行设置断点，逐步查看 `price`、`count`、`subtotal`。学会 Step Over、Step Into、Call Stack 与 Watch，比复制十个 `console.log` 更有帮助。

## 07. 第七个习惯：先修编辑器提示，再提交代码

ESLint 报了错误，不要为了显示“绿色”直接关掉规则。先判断这是真 bug，还是规则不适合当前项目。格式化工具和静态检查工具也不要混为一谈。

## 08. 第八个习惯：熟悉Git差异视图

提交前打开 Source Control，逐个看修改：有没有误改配置、有没有把 Token 写进去、有没有把调试代码留在项目里。

一次合理的提交，应能说清楚“修改了什么以及为什么”。

## 09. 第九个习惯：用工作区设置统一团队风格

```json
{
  "editor.formatOnSave": true,
  "editor.tabSize": 2,
  "files.trimTrailingWhitespace": true
}
```

这些设置可以保存在项目的 `.vscode/settings.json`，但不同团队应协调代码规范。不要把个人对字体、配色等偏好强制塞给所有同事。

## 10. 第十个习惯：把重复任务变成命令

比如自动运行检查：

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "检查代码",
      "type": "shell",
      "command": "npm run lint",
      "group": "test"
    }
  ]
}
```

放到 `.vscode/tasks.json`，通过 **Tasks: Run Task** 启动。前提是 `package.json` 里有 `lint` 脚本。

## 11. 一小时的训练方案

前十分钟用命令面板和快速打开；再十分钟练重命名和查引用；然后练断点、调用栈；最后完成一次多光标修改、格式化、Git diff 和任务执行。

过一周再看自己是不是还习惯用鼠标翻目录。编辑器的熟练程度，真正体现在**少打断思路，而不是手指有多快**。
