# 肆.2.2 Easydoc 等在线接口文档工具，应该怎么选？

在线 API 文档平台解决的是协作问题：产品、前端、后端和测试能够在同一个地方讨论字段、响应示例与修改记录。工具名字并非关键，关键是**文档是否可维护、可验证、可迁移**。

## 01. 需求清单比产品排名重要

评估 Easydoc 或其他在线平台时，至少问清楚这些问题：

1. 是否支持导入/导出 OpenAPI 等通用格式？如果平台停止服务，文档还能不能迁走？
2. 能否按环境管理 API Base URL、鉴权信息，并避免把私钥暴露给所有协作者？
3. 是否有版本历史、权限分级、变更审查和评论？
4. Mock 返回值、自动化测试和代码生成是产品自带还是第三方集成？
5. 是否支持私有化部署、数据备份与审计？

## 02. 一份可执行的协作流程

- 后端在设计阶段提交接口结构，而不是等开发结束才补文档。
- 前端根据规范完成 Mock 联调，记录有歧义的字段与边界情况。
- 后端实现接口，测试依据文档构造有效和无效请求。
- 发布前运行接口契约检查；破坏性变更需要版本策略或迁移说明。

## 03. 绝不能只靠截图传接口

截图没有机器可读的字段约束，无法做自动校验；聊天消息也很难追踪“后来改成什么”。把规范放进代码仓库并经过评审，通常更容易回溯。

平台的具体定价、在线状态和功能随时间变化，本章不虚构 Easydoc 当前还提供哪些套餐。读者选择产品时应直接核实服务商现行文档。
