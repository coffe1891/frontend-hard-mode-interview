# 肆.1.2 常用前端脚手架：到底替你做了什么？

脚手架能快速生成项目入口、构建配置和开发环境，**但业务结构、权限设计、部署回滚仍要自己负责。**

## 01. 别把框架、脚手架、构建工具混为一谈

- **React、Vue、Angular：** 管理组件和界面的框架或库。
- **Vite、Webpack：** 提供开发服务器、构建或打包能力。
- **脚手架：** 快速生成项目模板和初始配置。

举个例子：用 Vite 创建一个 Vue 项目：

```bash
npm create vite@latest my-app -- --template vue
cd my-app
npm install
npm run dev
```

不同工具版本、Node.js 版本与操作系统可能影响命令行为；遇到问题先检查生成器的版本要求。

## 02. 建完项目，第一件事不是写页面

生成项目后，先打开 `package.json` 看构建命令：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

这是常见的简化示意，不是完整可安装的 `package.json`。

- `npm run dev`：启动开发服务器，方便开发时刷新和热更新。
- `npm run build`：生成生产部署资源。
- `npm run preview`：本地预览构建输出，不应直接拿来当生产服务器。

## 03. 脚手架生成了什么配置？

很多项目至少要解决：

1. **代码入口：** 浏览器从哪个 HTML 和 JavaScript 模块启动应用？
2. **模块规则：** 如何加载 TypeScript、CSS、图片等资源？
3. **开发体验：** 怎样热更新、调试、规范化代码？
4. **发布方式：** 构建产物是什么、放到什么路径、缓存如何处理？
5. **团队规范：** 依赖锁文件、代码风格、环境变量如何统一？

以环境变量为例，Vite 的客户端代码可以使用符合规则的环境变量，但**放进前端打包产物的值本质上会被用户看到**。密钥、数据库密码不能放进去。

## 04. 脚手架也有坑

注意两件事：**目录不要过度设计**，小项目没必要生成几十个空目录；**插件不要堆叠**，格式化、测试工具装得太多反而增加维护成本。

## 05. 2026 年建新项目，别再跟着旧教程用 CRA

**React 官方在 2025 年 2 月宣布弃用 Create React App（CRA）**，不再推荐新项目使用。

旧教程常见命令：

```bash
npx create-react-app my-app
```

旧项目不必立刻迁移，但新项目应重新选型。

按需求选：

- **想练 React 组件、做纯客户端后台或小工具：** 可以直接用 Vite 的 React 模板。
- **需要服务端渲染、路由、数据加载和更完整的项目约定：** 按实际需求评估 React 官方推荐的应用框架。
- **只是写一个可复用的 npm 库：** 重点研究库构建、导出格式和类型声明，没必要搬来一套重型 Web 应用脚手架。

```bash
npm create vite@latest my-react-app -- --template react
cd my-react-app
npm install
npm run dev
```

创建前先检查 Node.js 版本要求。Vite 的环境要求会随着大版本升级而调整，**以官网当时的 Getting Started 为准**，不要机械照抄旧教程里写死的 Node 版本。

参考：[React：弃用 Create React App](https://react.dev/blog/2025/02/14/sunsetting-create-react-app)、[React：开始新项目](https://react.dev/learn/start-a-new-react-project)、[Vite 官方入门](https://vite.dev/guide/)。

## 06. 面试怎么答？

回答时分清：哪些由脚手架生成，哪些交给构建工具，哪些需要团队自行设计（权限、环境变量、测试、部署）。
