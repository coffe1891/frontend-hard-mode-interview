# 肆.1.2 常用前端脚手架：到底替你做了什么？

一个新同事进组，产品经理说：“今天开始做一个后台系统。”你打开空文件夹，发现项目还缺一大堆东西：入口 HTML、JavaScript 模块、构建命令、开发服务器、依赖包、环境配置……

脚手架就是帮你一次性搭好“房子的骨架”。但它不负责替你装修，也不意味着生成的项目一定适合长期维护。

## 01. 别把框架、脚手架、构建工具混为一谈

打个比方：

- **React、Vue、Angular 是你选择的装修与施工体系**，解决组件和界面如何组织。
- **Vite、Webpack 是加工厂**，处理模块、资源和构建产物。
- **脚手架是开工时提供的标准蓝图**，快速生成项目目录与起始配置。

举个例子：用 Vite 创建一个 Vue 项目：

```bash
npm create vite@latest my-app -- --template vue
cd my-app
npm install
npm run dev
```

不同工具版本、Node.js 版本与操作系统可能影响命令行为；遇到问题先检查生成器的版本要求。

## 02. 建完项目，第一件事不是写页面

请先打开 `package.json`，看看这几个东西：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

这是常见的简化示意，不是完整可安装的 `package.json`。

- `npm run dev`：启动开发服务器，方便开发时刷新和热更新。
- `npm run build`：生成生产部署资源。
- `npm run preview`：本地预览构建输出，不应直接拿来当生产服务器。

**创建命令只是入口，看懂脚手架留下了什么，才算会用。**

## 03. 脚手架生成了什么配置？

很多项目至少要解决：

1. **代码入口：** 浏览器从哪个 HTML 和 JavaScript 模块启动应用？
2. **模块规则：** 如何加载 TypeScript、CSS、图片等资源？
3. **开发体验：** 怎样热更新、调试、规范化代码？
4. **发布方式：** 构建产物是什么、放到什么路径、缓存如何处理？
5. **团队规范：** 依赖锁文件、代码风格、环境变量如何统一？

以环境变量为例，Vite 的客户端代码可以使用符合规则的环境变量，但**放进前端打包产物的值本质上会被用户看到**。密钥、数据库密码不能放进去。

## 04. React项目该选哪个脚手架？

取决于需求。若只是练习组件和简单客户端应用，轻量 Vite 模板可能足够；若要服务端渲染、路由约定、数据加载等完整能力，可评估成熟的 React 应用框架。

不要只问“哪个更火”，要问“这项目是否需要 SSR、SEO、静态生成、复杂路由、权限、国际化和部署方案”。

## 05. 脚手架也有坑

**依赖版本过旧。** 脚手架只是一张生成时的蓝图，新项目应核对依赖安全与兼容情况。

**目录过度设计。** 一个按钮项目生成几十个空目录，不会提高工程质量。

**插件堆叠。** 一开始就加十几种格式化、测试、构建插件，反而增加团队维护成本。

## 06. 面试怎么答？

试着说明：从空目录到部署页面，哪些工作脚手架替你完成、哪些交给构建工具、哪些是你必须自己决定的工程规则。能把这些边界讲清楚，比背十条 `create` 命令强。
