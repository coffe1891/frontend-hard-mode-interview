# 肆.1.2 常用前端脚手架：到底替你做了什么？

脚手架不是魔法。它主要负责**生成项目初始结构、安装或声明依赖、提供开发与构建命令**。真正的难点，是能否看懂生成之后的项目，而不是会不会敲一条创建命令。

## 01. 脚手架、构建工具、框架的关系

- **框架**：React、Vue、Angular，帮助组织应用和界面逻辑。
- **构建工具**：Vite、Webpack、Rollup 等，处理模块依赖、开发服务器、资源变换与生产构建。
- **脚手架**：为项目选择并生成一套初始化配置。某些框架也提供自己的项目生成工具。

例如使用 Vite 创建 Vue 或 React 项目，生成后一般会有 `package.json`、入口 HTML、源代码目录和构建脚本。Vite 不是 React/Vue 的替代品；脚手架也不是运行时框架。

## 02. 常见选择

- **Vite**：适合许多现代 Vue、React 和原生前端项目，开发阶段充分利用原生 ESM。
- **Angular CLI**：与 Angular 工程体系集成，用于创建、构建、测试和生成代码。
- **Next.js 等应用框架的初始化工具**：为 React 的路由、服务端渲染、部署模式提供成套约定。
- **公司内部脚手架**：负责统一代码规范、目录结构、CI、监控和鉴权接入。

工具命令和推荐模板会随版本变动，执行前应查看各自官方文档，不宜把几年前复制的命令当成永远有效。

## 03. 面试官想听什么？

**问题：为什么不能直接复制上一份项目？**

可以复制，但需要评估依赖是否过期、环境变量是否混入敏感信息、构建参数是否适用。一个好的脚手架应该让初始化过程可重复、容易审计，而不是把隐藏约定越堆越厚。

**问题：如何制作公司的脚手架？**

从最小模板开始，定义可配置项（项目名、技术栈、包管理工具）、输入校验和文件替换；再测试生成结果能否安装、运行、构建，并约束版本兼容性。切忌在模板里硬编码密钥。
