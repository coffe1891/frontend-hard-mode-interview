# 肆.3.3 Sublime Text还有必要学习吗？

Sublime Text 还有必要学吗？我觉得这问题跟“锤子和电钻哪个好”差不多，要先看你准备干什么。

临时改一份配置、打开一个大文本文件，轻量编辑器可能很顺手。可要长期维护 React、Vue、TypeScript 工程，还要调试、查引用、跑测试，那又是另一套要求。

所以别忙着给编辑器排座次，看看自己每天到底在做什么。

## 01. Sublime Text擅长什么？

Sublime Text 的好处是利落，开文件、批量查找、多光标修改都很顺手。要是只需要迅速改几行文本，我有时反而觉得功能太多的 IDE 有点累赘。

它并不自动等于“功能少”：它有项目管理、构建系统和扩展机制。但与 VS Code 的语言服务器、调试和远程开发生态相比，两者的重点与默认集成体验不一样。

## 02. 场景一：把一百行日志中的某个字段改掉

假设日志长这样：

```text
user=alice status=200
user=bob status=404
user=carol status=200
```

你想把全部 `status=200` 换成 `status=OK`。用查找替换一次完成即可；再结合正则可以处理更复杂格式。但修改日志前先确认是否用于真实审计，生产日志通常不应被改写。

## 03. 场景二：同时编辑多个相同位置

多光标适合统一修改重复结构，比如十个变量名、十组 HTML 属性。Sublime Text 的多选区功能很成熟，不过具体快捷键受系统和配置影响。

如果是大规模改名，涉及作用域、导入引用和类型语义，VS Code 的 Rename Symbol 往往比纯文本替换更稳妥。

## 04. 一个正则查找例子

有一组简单数据：

```text
order-1001
order-1002
user-1003
```

正则 `^order-(\d+)$` 可以匹配以 `order-` 开头、后面只有数字的整行。替换时可引用捕获组，但具体替换格式应以编辑器正则引擎和版本规则为准。

## 05. 到底应该选谁？

说到这里，究竟该选哪个？我觉得看场景就好，别搞成阵营之争：

- **偶尔临时编辑文本：** 一个轻量编辑器可能更方便。
- **长期维护 Vue/React/TypeScript 工程：** 需要调试、类型提示、Git 协作，VS Code 及其生态通常更合适。
- **团队已有稳定工具链：** 不必为了换编辑器而重新折腾所有配置。

软件工程的生产力不是“谁打开文件快半秒”，而是整个需求开发、测试、调试、发布流程是否顺畅。

## 06. 面试里最有价值的回答

别把编辑器品牌当技术能力。说明你如何批量编辑、查引用、调试、处理冲突和核对变更。真正的工程师，工具变了也应该能快速把任务做好。

编辑器换来换去并不会让代码自动变好。真正该练的是查问题、看差异和快速理解陌生代码的能力。
