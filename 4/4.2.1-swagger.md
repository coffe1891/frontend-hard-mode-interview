# 肆.2.1 用Swagger/OpenAPI解决前后端接口沟通问题

前端同事写好页面，后端说：“接口已经好了，你直接调吧。”你一调用，发现后端给的是 `user_name`，前端以为是 `username`；状态码 200 里还塞着各种业务错误；文档里的参数跟真实接口又不一样。

这不是“前后端配合不好”这么简单，而是**大家缺少一份明确、可检查、可版本管理的接口契约**。

## 01. 先区分Swagger和OpenAPI

- **OpenAPI Specification（OAS）**：一种描述 HTTP API 的规范。
- **Swagger UI**：把 OpenAPI 描述展示成可以查看、尝试请求的网页。
- **Swagger Editor** 等工具：帮助编写和检查描述。

可以理解为：OpenAPI 是合同格式，Swagger UI 是展示合同的工具。它们不是同一个东西。

## 02. 一个最小的接口合同长什么样？

假设接口用于按 ID 查询用户：

```yaml
openapi: 3.0.3
info:
  title: 用户服务
  version: 1.0.0
servers:
  - url: https://api.example.com
paths:
  /users/{id}:
    get:
      summary: 根据ID查询用户
      parameters:
        - name: id
          in: path
          required: true
          schema:
            type: integer
      responses:
        '200':
          description: 查询成功
          content:
            application/json:
              schema:
                type: object
                required: [id, name]
                properties:
                  id:
                    type: integer
                  name:
                    type: string
        '404':
          description: 用户不存在
```

这个例子没有实际服务，只是一份 API 描述。真正调用 `https://api.example.com` 不保证有对应接口。

从这份文档，前端就能知道：路径是 `/users/{id}`，ID 是必填整数，200 结果至少有 `id` 和 `name`，查不到则可能是 404。

## 03. 为什么字段名变一下也算大事？

假设老版本返回：

```json
{ "id": 10, "name": "张三" }
```

新版本突然改成：

```json
{ "userId": 10, "displayName": "张三" }
```

后端觉得“只是改两个名字”，前端却可能直接显示空白。API 的字段名就是合同的一部分，不能当内部变量随意改。

如果必须改，应该规划版本兼容、迁移窗口与回滚策略，并通过契约测试检查，避免一个改动把多个客户端一起弄坏。

## 04. 怎么避免文档写了却没人维护？

一个务实的流程：

1. 需求评审时先约定路径、方法、参数、成功响应和错误响应。
2. 把 OpenAPI 文档放进版本控制，与接口实现一起做代码评审。
3. 前端根据合同生成类型或模拟响应，尽早开展页面开发。
4. 后端实现完成后，用自动化校验检查响应是否符合合同。
5. 发生不兼容变更时，明确通知客户端和版本迁移计划。

**接口文档最怕成为“上线之后再补”的装饰品。**

## 05. 鉴权和错误码怎么描述？

如果接口需要 Bearer Token，应该在 OpenAPI 里声明安全方案，而不是只写一句“带 Token 就行”。

```yaml
components:
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
security:
  - bearerAuth: []
```

上面片段需要与完整 OpenAPI 文档合并使用。Token 不应该写成真实固定值放在公开文档里。

对于错误码，除了 HTTP 状态，还应定义稳定的业务错误结构，例如 `{ code, message, requestId }`。前端可根据 `code` 做展示，排障时根据 `requestId` 查服务端日志。

## 06. 面试官会追问什么？

**有了Swagger UI就代表后端实现符合文档吗？** 不代表。展示出来的合同可能已经过期，需要验证与测试。

**自动生成TypeScript类型是否等于接口安全？** 不等于。TypeScript 主要提供编译期检查，运行时的网络数据仍可能不符合约定，必要时要做运行时校验。

**什么时候不用OpenAPI？** 非 HTTP API、特殊事件协议或非常简单的内部函数可能需要其他契约方式，不能一个工具包办所有通信。
