# 贰.1.7 实战：阿里巴巴前端面试题

## 贰.1.7.1 求数组子数组之和的最大值

这道题源自微软面试题，后来被阿里巴巴用上了，据说只有20%的人能给出时间复杂度为 $$O(N^3)$$ 的答案，给出 $$O(N)$$ 解的人极少。题目如下：

> 一个有N个整数项的一维数组，这个数组有很连续多子数组，那么子数组之和的最大值是多少？

举例：

* `[ 1,-3, 3, 4, 5,-3]`返回12；
* `[-1,-2,-3,-4,-9,-8]`返回-1；

### 解法一

问题其实是求从下标为`i`和`j`之间的连续数组项之和的最大值。

```js-run
function fn(arr) {
    let maxSum=-Infinity, len = arr.length;
    for (let i = 0; i < len; i++) {
        for (let j = i; j < len; j++) {
            let sum=0;
            for (let k = i; k <= j; k++) {
                sum += arr[k];
            }
            if (sum > maxSum){
                maxSum = sum;
            }
        }
    }
    console.log(maxSum);
}
fn([ 1, -3,  3,  4,  5, -3]);//>> 12
fn([-1, -2, -3, -4, -9, -8]);//>> -1
```

上面代码有3个for循环，因此时间复杂度是 $$O(N^3)$$ 。

### 解法二

如果注意到 $$A_i+...+A_j=A_i+...A_j-_1+A_j$$ ，那么可以将解法一精简如下：

```js-run
function fn(arr) {
    let maxSum=-Infinity, len = arr.length;
    for (let i = 0; i < len; i++) {
        let sum = 0;
        for (let j = i; j < len; j++) {
            sum += arr[j];
            if (sum > maxSum){
                maxSum = sum;
            }
        }
    }
    console.log(maxSum);
}
fn([ 1, -3,  3,  4,  5, -3]);//>> 12
fn([-1, -2, -3, -4, -9, -8]);//>> -1
```

上面代码第6行就体现了 $$A_i+...+A_j$$ ，与解法一的第三个for循环其实是等效的。因此可以精简掉一个for循环，精简之后的算法时间复杂度为 $$O(N^2)$$ 。能做到这样，其实已经不错的，但是还不够，有没有更低时间复杂度的解法呢？有！

### 解法三

若用**动态规划法**，应该先有一个“看起来更加毫无规律”的样本数据，这里选\[ 1, -3, 3, 4, 5, -3\]，然后做下面表格分析规律得出**状态转移方程**：

| 步骤 | 操作 | 累加的子数组之和 | 最大子数组和 |
| :--- | :--- | :--- | :--- |
| 1 | 加1 | 1 | 1 |
| 2 | -3 | -2 | -2 |
| 3 | 之前的和＜0，舍弃，直接从3开始，+3 | 3 | 3 |
| 4 | +4 | 7 | 7 |
| 5 | +5 | 12 | 12 |
| 6 | -3 | 9 | 12 |

用数学归纳法得出状态转移方程如下：

 令 `bestEnd[i]` 表示**必须以第 i 项结尾**的连续子数组的最大和，则：

$
bestEnd[i]=\max(array[i], bestEnd[i-1]+array[i])
$

最终答案是所有 `bestEnd[i]` 中的最大值。`bestEnd[0]=array[0]`，因此全为负数时也能正确返回最大的那个负数。这个算法通常称为 Kadane 算法。

```js-run
function fn(array) {
  if (!Array.isArray(array) || array.length === 0) {
    throw new TypeError('必须传入非空数组');
  }
  let currentSum = array[0];
  let maxSum = array[0];
  for (let i = 1; i < array.length; i++) {
    currentSum = Math.max(array[i], currentSum + array[i]);
    maxSum = Math.max(maxSum, currentSum);
  }
  return maxSum;
}
console.log(fn([1, -3, 3, 4, 5, -3])); // 12
console.log(fn([-1, -2, -3, -4]));   // -1
```

时间复杂度为 $$O(N)$$ 。

## 贰.1.7.2 硬币找零

题目为：

> 从面值为 1,2,5,10 的硬币中找零 36 块钱，最少要 几 枚硬币？

### 解法一：动态规划

这是典型的动态规划问题。所谓动态规划，也即问题分成多个步骤，每一步的选择是可以动态调整的，所有步骤完成之后，最后求最优解。比如求两点之间的最优路径，多种组合方案的最优方案。**这类问题，可以分解成对每一步求最优解，然后将每步的最优解组合，即为最终最优解。**

本题求最少硬币数，也可以用动态规划法求解。首先要归纳出一个**状态转移方程。**给定的金额`i`，最少硬币数为`f(i)`，硬币面值为`j`，它们之间的关系可以用方程表达如下（该方程即为**状态转移方程**）：

$$
f(i)=f(i-j)+1
$$

有了上面这个状态转移方程，可以看出是一个递归求解过程，所以，此类问题就很好解了，代码如下：

```javascript
/**
 * 硬币找零 之 动态规划法。
 * 状态转移方程 DP(i)=DP(i-j)+1，其中i是金额，j是硬币面值。
 * @param {array} coins 硬币面额的数组
 * @param {number} amount 给定的金额数
 */

(function (coins, amount) {
    //优化，缓存递归过程中已经计算过的金额数
    let cache = new Map();

    //如果金额和面值恰好相等，1枚硬币就能完成
    coins.forEach(coin => {
        cache.set(coin, 1);
    });

    console.time("coffe1891");

    let DP = function (amount) {
        if (amount <= 0)
            return 0;
        else if (cache.has(amount))
            return cache.get(amount);
        else {
            //缓存方案
            let tmpArr = [];
            for (let i = 0; i < coins.length; i++) {
                let coin = coins[i];
                if (amount - coin > 0) {//非法钱数不计算
                    //递归
                    let v = DP(amount - coin) + 1;
                    tmpArr.push(v);
                }
            }

            //从方案中选最优的
            tmpArr.sort((a, b) => a - b);
            cache.set(amount, tmpArr[0]);
            return tmpArr[0];
        }
    }
    console.log("从面值为 " + coins + " 的硬币中找零 " + amount + " 块钱，最少要 " + DP(amount) + " 枚硬币");
    console.timeEnd('coffe1891');
})([1, 2, 5, 10], 36);
```

因此我们发现一个规律：**可用动态规划法解题的关键，在于找到状态转移方程，通过观察该方程，可以更快知道解题的具体算法思路**。

### 解法二：贪心算法

每次我们都优先取最大的硬币面额，直到剩余金额不足最大面额时，我们会取第二大的面额，以此类推，从而实现总硬币数最小的目的。其思想非常简单，我们直接上代码：

```js-run
/**
 * 硬币找零 之 贪心算法
 */
(function (coins, amount) {
    let s = new Date().getTime();
    let greedy = function (amount) {
        let total = 0;//已找金额
        let change = [];//放硬币的罐子
        for (let i = coins.length-1; i >= 0; i--) {
            let coin = coins[i];
            while (total + coin <= amount) {
                change.push(coin);
                total += coin;
            }
        }
        return change.length;
    }
    console.log("从面值为 " + coins + " 的硬币中找零 " + amount + " 块钱，最少要 " + greedy(amount) + " 枚硬币");
    let e = new Date().getTime();
    console.log("耗时  " + (e - s) + "  ms");
})([1, 2, 5, 10], 36);
```

## 贰.1.7.3 不要只记住答案：为什么连续子数组能用O(N)？

前面把几种解法都写出来了，可我认为最值得琢磨的不是 `O(N)` 这个答案，而是：**为什么前面的和变成负数，有时候就该扔掉？**

这个地方不懂，代码背得再熟也只是背口诀。我们拿 `[1, -3, 3, 4, 5, -3]` 一项一项走。

例如 `[1, -3, 3, 4, 5, -3]`：

- 走到第 1 个数，当前最好是 1；
- 加上 −3，当前连续和变成 −2；
- 再遇到 3，如果继续接着 −2 走，只能得到 1；不如从 3 重新开始。
- 后面接着加 4 和 5，最终得到 12。

因此每一步都在问：**“把当前元素接在前面”与“从当前元素重新开始”，哪个更划算？**

```js-run
function maxSubarray(nums) {
  if (!Array.isArray(nums) || nums.length === 0) {
    throw new RangeError('需要非空数组');
  }
  let current = nums[0];
  let best = nums[0];

  for (let i = 1; i < nums.length; i++) {
    current = Math.max(nums[i], current + nums[i]);
    best = Math.max(best, current);
  }
  return best;
}

console.log(maxSubarray([1, -3, 3, 4, 5, -3])); // 12
console.log(maxSubarray([-5, -1, -9])); // -1
```

为什么初始化不能写 `best = 0`？因为数组可能全部为负数。要求的是**非空连续子数组**，不能把“不选任何元素”算作结果。这个边界往往比主体算法还容易丢分。

## 贰.1.7.4 硬币找零：完整的自底向上版本

上面的递归 + 缓存版本能说明思路，但实际工程中更常见的是从 0 元一步步算到目标金额。

假设硬币面额是 `[1, 2, 5]`，要找 7 元。

- 找 0 元需要 0 枚；
- 找 1 元需要 1 枚；
- 找 2 元需要 1 枚；
- 找 3 元可以从 2 元再加 1 枚，得到 2 枚；
- ……
- 找 7 元可以由 5 元 + 2 元组成，需要 2 枚。

```js-run
function minCoins(coins, amount) {
  if (!Number.isInteger(amount) || amount < 0 ||
      !Array.isArray(coins) ||
      coins.some(c => !Number.isInteger(c) || c <= 0)) {
    throw new RangeError('金额必须非负，硬币面额必须为正整数');
  }

  const dp = Array(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (let value = 1; value <= amount; value++) {
    for (const coin of coins) {
      if (value >= coin) {
        dp[value] = Math.min(dp[value], dp[value - coin] + 1);
      }
    }
  }
  return Number.isFinite(dp[amount]) ? dp[amount] : -1;
}
console.log(minCoins([1, 2, 5], 7)); // 2
console.log(minCoins([2], 3));       // -1，无法凑出
```

这里的状态是 `dp[i]`：凑出金额 i 时需要的最少硬币数。`Infinity` 表示目前还凑不出来。每次尝试一枚硬币，比较各种候选方案，取最小值。

时间复杂度为 `O(amount × coins.length)`，空间复杂度为 `O(amount)`。

## 贰.1.7.5 给贪心法一个反例

```javascript
console.log(minCoins([1, 3, 4], 6)); // 2，即3+3
```

如果按面额从大到小拿，贪心会选 `4+1+1`，用了 3 枚。**所以贪心并不保证对任意硬币体系都正确。**

而且，原文给出的面额 `[1, 2, 5, 10]` 与 36 元案例，确实可以用贪心找到 5 枚，但这只是该题输入的结果。不能从一个正确样例推导出算法适用于所有找零问题。

## 贰.1.7.6 面试官真正看重什么？

假如我是面试官，看到你一上来就默写一个公式，未必觉得多厉害。我反而想听你怎么从三层循环一步步推到两层，再想到只保留“以当前位置结尾的最好结果”。能自己推出来，才算真懂。

做动态规划时，习惯回答四个问题：

1. **状态表示什么？** 例如当前下标结尾的最大和。
2. **状态如何转移？** 接上前面的和，还是从当前元素重新开始？
3. **初始条件是什么？** 第一项，还是金额为 0？
4. **最终答案在哪里？** 有的题直接是 `dp[n]`，有的题要比较全部中间状态。

别把“会写出代码”当成理解算法的终点。能解释每一步为什么正确，才是真正的 Hard 模式。

做算法还是那句话：边界先问清楚，最优目标先说清楚，代码为什么正确再解释清楚。别把背“秒杀模板”当成技术水平。
