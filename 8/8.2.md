# 捌.2 TypeScript：别让五个布尔值把页面状态搞乱

做个商品搜索页，产品经理要求你支持加载、成功、失败、空结果四种状态。

很多朋友第一反应是写四五个布尔值：`isLoading`、`isError`、`isEmpty`……问题是这些值一旦组合起来，**“正在加载，同时又显示成功”** 的怪事就可能出现。

如果状态之间本来就互相排斥，何必给自己挖坑？

## 01. 用判别联合类型表示状态

```typescript
type SearchState =
  | { status: "idle" }
  | { status: "loading"; keyword: string }
  | { status: "success"; items: string[] }
  | { status: "error"; message: string };

function assertNever(value: never): never {
  throw new Error("遗漏了状态：" + JSON.stringify(value));
}

function renderText(state: SearchState): string {
  switch (state.status) {
    case "idle": return "请输入关键词";
    case "loading": return "正在搜索：" + state.keyword;
    case "success": return state.items.length
      ? "找到 " + state.items.length + " 条结果"
      : "暂时没有结果";
    case "error": return "搜索失败：" + state.message;
    default: return assertNever(state);
  }
}

console.log(renderText({ status: "loading", keyword: "手机" }));
// >> 正在搜索：手机
```

这里 `status` 不只是一段字符串。它同时告诉 TypeScript：当 `status` 是 `"error"` 时，才有 `message`；当它是 `"success"` 时，才有 `items`。

如果明天新增 `"cancelled"` 状态，却忘了改 `renderText()`，严格类型检查可以借助 `assertNever` 提醒你有情况没处理。

## 02. 别把类型检查当成产品设计

它能防止很多无意义的状态组合，却不能替你决定：

搜索词变了，旧请求回来怎么办？用户已经离开页面，回调还要不要更新？错误提示要不要重试？

这些是**工程设计问题**。TypeScript 能帮你表达规则，却不会自己想出规则。

## 03. 练习

把上面的状态加上 `cancelled`，要求显示“已取消搜索”。先故意不修改 `switch`，观察类型检查怎样报错；再补上分支。
