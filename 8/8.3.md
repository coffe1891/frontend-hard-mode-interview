# 捌.3 TypeScript 泛型：AI 写得快，你得知道哪里会出错

泛型这东西，刚接触时看着像数学题。其实你只要记住一件事：**我希望同一段逻辑能处理不同类型的数据，但不能把类型信息全扔了。**

比如前端经常要从商品列表、订单列表里按 ID 找数据。

## 01. 先看一个不合适的写法

```typescript
function getById(items: any[], id: string): any {
  return items.find(item => item.id === id);
}
```

它当然能运行，可返回值是什么？编译器也不知道。你拼错属性名，编辑器很可能连个提醒都没有。

改成泛型：

```typescript
type WithId = { id: string };

function getById<T extends WithId>(
  items: readonly T[],
  id: string
): T | undefined {
  return items.find(item => item.id === id);
}

type Product = { id: string; price: number; name: string };

const products: Product[] = [
  { id: "p1", name: "耳机", price: 199 },
  { id: "p2", name: "键盘", price: 299 }
];

const found = getById(products, "p2");
console.log(found?.price); // >> 299
```

这里 `T` 就是“调用者传来的具体数据类型”。

`T extends WithId` 的意思是：你可以传任何类型，但至少得有一个字符串 `id`。返回值仍保留完整的 `Product` 类型。

另外，找不到数据时 `find()` 会返回 `undefined`，所以返回类型必须写成 `T | undefined`。**把这个可能性藏掉，是很多 AI 代码特别爱犯的毛病。**

## 02. 一个常见误区

泛型能保留编译时的类型信息，但它不能保证后端真的返回 `Product`。从网络拿到的 JSON，仍然需要像[第一篇](8.1.md)那样做运行时校验。

## 03. 给 AI 出三道验收题

让 AI 写一个支持商品、订单、用户的通用查找函数，然后检查：

1. 查找不到是否返回 `undefined`，调用方有没有处理。
2. 传入没有 `id` 的数据，编译器是否会拒绝。
3. 如果拿到的 ID 是数字，AI 是不是偷偷用 `as any` 让错误消失了。

这三道题，比让 AI 把 `<T>` 写得花里胡哨有用得多。
