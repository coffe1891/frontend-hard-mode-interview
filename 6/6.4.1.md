# 陆.4.1 什么是响应式编程？

如果你用过 Excel，理解响应式编程就不难了。

A1 填 10，B1 填 20，C1 写 `=A1+B1`。以后 A1 改成 30，C1 自己就变成 50。你并没有再按一下“重新计算 C1”，因为系统早就知道谁依赖了谁。程序里也可以用同样的思路处理数据变化。

## 01. 先看非响应式写法

```js-run
let price = 20;
let quantity = 2;
let total = price * quantity;

quantity = 3;
console.log(total); // 40，仍是旧值
total = price * quantity; // 你必须主动再算一次
```

如果很多结果都依赖很多输入，手工更新很容易漏掉。响应式编程倾向于把“谁依赖谁”“变化怎么传播”描述清楚。

## 02. 响应式不等于自动轮询

一个粗糙方案是每隔 100ms 检查一次所有变量，看看哪些变了。数据一多，这种办法既浪费资源，又可能更新不及时。

更常见的设计思路是**建立依赖关系，只通知真正需要重新计算的部分**。例如 Vue 的响应式系统会在读取数据时追踪依赖，在数据更新时触发有关计算或组件更新。

参考前面的 [Vue 数据响应式原理](../3/3.3.1.md)，我们用几十行代码手写过这种机制。

## 03. 另一种响应式：随时间到来的数据流

还有一种场景，变化不是来自某个固定变量，而是不断到来的事件。比如搜索框里每打一个字，都会产生一次输入事件。我们可以把它们连成一条流，按需要筛选、防抖、转换。

```javascript
// 原生浏览器事件的简化例子
const input = document.querySelector('#search');
input.addEventListener('input', event => {
  const keyword = event.target.value.trim();
  console.log('新的搜索词：', keyword);
});
```

如果业务变复杂，RxJS 可以帮助组合“事件流 → 防抖 → 请求 → 结果”的处理过程。相关实例见 [RxJS](../5/5.3.2.md)。

## 04. 响应式编程、响应式布局是一回事吗？

不是。CSS 里的响应式布局主要关注页面如何适配不同屏幕；Reactive Programming 关注数据变化和事件的传播。中文翻译相同，但讨论的技术层次完全不同。

## 05. 实战该怎样选择？

那到底什么时候用响应式系统？别把问题复杂化。

如果只是算两数之和，一个普通函数就够了；数据变化需要自动更新派生结果，可以考虑响应式状态；连续事件需要取消、合并与异步处理，再考虑 RxJS 这类工具。下面把几种场景列出来：

- 需要从状态计算派生值：可以使用 Vue 的 `computed`、Angular Signal 的 `computed` 等机制。
- 需要处理连续事件、异步组合和取消：可以评估 RxJS 等流式工具。
- 只是一次简单函数调用：普通 JavaScript 就很清楚，不必强行上响应式框架。

## 06. 最大的代价是什么？

自动传播变化节省了手动同步代码，却也带来“为什么这块界面更新了”的追踪难题。项目中应避免到处共享可变对象，明确状态归属，减少循环依赖，并使用开发者工具追踪更新链。

记住：响应式编程要解决的是**变化如何传播**，而不是让所有变量都“自动变魔术”。

响应式的本事是帮我们传播变化，可传播关系也可能绕得很深。谁改了数据、谁依赖它，还是要能说得清清楚楚。
