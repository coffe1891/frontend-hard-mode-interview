# 陆.3.3 Pointfree无参数风格编程

你要处理一串用户名：去掉首尾空格，把字母转成大写，再加一个感叹号。普通写法很直观：

```javascript
function normalize(name) {
  return name.trim().toUpperCase() + '!';
}
console.log(normalize('  alice  ')); // ALICE!
```

所谓 Pointfree，就是把这些步骤拆成函数，再组合起来时**不显式写那个待处理的数据参数**。

## 01. 一步步改成Pointfree

```javascript
const trim = text => text.trim();
const upper = text => text.toUpperCase();
const exclaim = text => text + '!';

const pipe = (...steps) => value =>
  steps.reduce((result, step) => step(result), value);

const normalize = pipe(trim, upper, exclaim);
console.log(normalize('  alice  ')); // ALICE!
```

注意 `normalize` 的定义：只描述了“修剪→大写→感叹号”，没有直接出现 `name`。但调用时仍然传入了具体数据。

## 02. 为什么有人喜欢它？

当一项业务需要执行多步转换时，组合式写法会把处理步骤排列得很清楚。每个小函数可以独立测试、重用，也方便增加或删除步骤。

例如对文章标题做规范化：

```javascript
const normalizeTitle = pipe(
  text => text.trim(),
  text => text.replace(/\s+/g, ' '),
  text => text.toUpperCase()
);
console.log(normalizeTitle('  hello   world ')); // HELLO WORLD
```

## 03. 别让“没有参数”变成“没人看懂”

如果你写成 `pipe(f, g, h, x, y, z)`，团队里没人知道这些字母代表什么，那就完全违背了可读性的目的。

另一个隐患是函数签名不匹配。`['10','11','12'].map(parseInt)` 会得到意料之外的结果，因为 `map` 还会传入数组下标，而 `parseInt` 把第二个参数当进制。应写成 `.map(x => parseInt(x, 10))`。

## 04. Pointfree和柯里化是同一个东西吗？

不是。Pointfree 是代码表达风格，柯里化是函数参数组织方式。柯里化有时有助于提前固定部分配置，让小函数容易组合，但没有“所有函数都必须柯里化”的规则。
